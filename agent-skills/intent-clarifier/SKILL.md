# 요청 의도 정리하기

사용자의 말을 임의로 바꾸거나 범위를 넓히지 않고, AI가 바로 이해하고 실행할 수 있는 요청으로 정리한다.

## 정리 순서

1. 사용자가 이루려는 목적을 한 문장으로 추린다.
2. 요청에 포함된 대상, 범위, 제약, 원하는 결과물을 구분한다.
3. 중복·감탄·배경 설명은 줄이고, 의미를 바꾸는 조건은 남긴다.
4. 모호한 부분은 추측해 채우지 말고 `확인이 필요한 점`으로 분리한다.
5. 정리한 내용이 맞는지 사용자에게 확인받는다. 사용자가 동의하기 전에는 이를 확정된 의도나 최종 요청으로 단정하지 않는다.
6. 동의한 뒤 실행 가능한 최종 요청을 짧게 제시한다.

## UI 표현을 요청으로 바꾸기

화면 요소를 일상 표현으로 설명하면 [UI 사전](references/ui-dictionary.md)에서 해당 표현과 구분 기준을 찾아 읽는다. 일반적인 요청 정리에는 사전이 필요하지 않다.

- 동작과 문맥이 맞으면 정식 명칭에 짧은 풀이를 붙인다. 예: 드로어(화면 옆에서 나오는 패널).
- “팝업”, “슬라이드”처럼 여러 뜻이면 후보의 동작 차이를 설명하고, 요청을 정리하는 데 필요한 질문만 한다. 이름을 임의로 확정하지 않는다.
- UI 요청은 위치·요소 이름·개수·동작/조건 중 사용자가 제공한 정보로 구성한다. 빠진 정보가 결과에 영향을 주면 `확인이 필요한 점`에 남긴다. 사전의 설명을 사용자의 요구사항으로 추가하지 않는다.
- 사전에 없거나 문맥과 맞지 않으면 원래 표현을 유지하고 필요한 동작을 확인한다. 요청 정리를 넘어 구현이나 도구 선택까지 수행하지 않는다.

예: “FAQ를 누르면 답이 펼쳐지게 해줘” → “FAQ를 아코디언(접고 펼치는 목록)으로 구성해, 질문을 누르면 해당 답변이 펼쳐지게 해 주세요.” 항목 수나 여러 답변의 동시 열림 여부는 이 요청에서 확정하지 않는다.

## CSS 증상을 요청으로 바꾸기

“글자가 잘려요”, “폰에서 옆으로 밀려요”처럼 화면 문제를 말하면 [CSS 사전](references/css-dictionary.md)에서 해당 증상과 관련 용어를 찾아 읽는다.

- 요청은 문제 위치·관찰한 증상·발생 환경·원하는 결과 중 제공된 정보로 정리한다. 수정에 필요한 정보만 `확인이 필요한 점`에 남긴다.
- 사전의 원인 후보는 진단 결과가 아니다. 원인을 확인하지 않았다면 “원인을 조사하고 원하는 동작으로 수정해 주세요”로 정리한다. `overflow: hidden` 같은 처방을 임의로 요구사항에 넣지 않는다.
- 가운데 정렬의 대상, 마지막 줄 배치, 줄바꿈 방식처럼 의도에 따라 결과가 달라지면 그 차이만 쉽게 설명해 확인한다. 이미 말한 조건은 다시 묻지 않는다.
- 사전에 CSS 후보가 있어도 이미지 로딩 실패나 클릭 불가 등이 반드시 CSS 문제라고 단정하지 않는다.

예: “폰에서 화면이 옆으로 밀려요” → “휴대폰에서 페이지가 가로로 밀리는 원인을 조사하고, 화면 너비 안에서 볼 수 있도록 수정해 주세요.” 기종이나 발생 페이지가 필요하면 확인하고, 특정 CSS 속성은 확정하지 않는다.

## 확인 절차

정리 결과를 제시한 뒤 다음처럼 한 문장으로 확인한다.

`제가 이해한 요청이 맞나요? 맞다면 이 내용으로 진행하겠습니다.`

사용자가 수정하면 수정된 내용을 다시 정리해 확인받는다. 단순히 문장 표현만 다듬어 달라는 요청처럼 사용자가 이미 의도를 명시한 경우에는 확인 질문을 생략할 수 있다.

## 출력 형식

```text
목적: [사용자가 하려는 일]
조건: [반드시 지켜야 할 조건]
결과물: [원하는 결과]

정리된 요청:
[AI에게 그대로 전달할 한 단락 또는 짧은 목록]

확인이 필요한 점:
- [없으면 이 항목을 생략]

확인: 제가 이해한 요청이 맞나요? 맞다면 이 내용으로 진행하겠습니다.
```

사용자가 단순히 문장만 다듬어 달라고 했다면 목적·조건 표와 확인 질문을 생략하고 다듬은 문장만 제공한다. 사용자의 결정을 대신하거나, 확인되지 않은 요구사항을 추가하지 않는다.

## 예시

입력: “우리 앱 로그인 좀 고쳐줘. 요즘 가끔 풀리고 사람들도 불편하대. 보안은 유지하면서 빨라졌으면 좋겠어.”

정리된 요청: “앱 로그인 세션이 간헐적으로 만료되는 원인을 조사하고 수정해 주세요. 기존 인증 보안 수준은 유지하면서 재로그인 횟수와 로그인 지연 시간을 줄여 주세요. 원인, 변경 내용, 테스트 결과를 함께 설명해 주세요.”
